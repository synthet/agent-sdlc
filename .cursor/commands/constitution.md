# /constitution — Project principles

Use to **draft or refine** stable principles that specs and plans should respect (workflow analog to “constitution” in spec-first kits). This is **markdown intent**, not executable policy—runtime guardrails live in the application repo.

## Inputs

- Greenfield (no doc yet) **or** path to an existing constitution / principles file.
- Team constraints from **AGENTS.md** (stack, boundaries).

## Output

1. **Purpose** — Why the document exists.
2. **Principles** — Numbered or short bullets (tradeoff guidance).
3. **Decision weights** — Order when principles conflict.
4. **Non-negotiables** — What specs must not violate.
5. **Quality bar** — Reviews, testing/eval expectations (pointers only).
6. **Review cadence** — When to revisit.

## Done when

- Principles are concrete enough to **judge** new specs and plans without re-debating basics each time.
